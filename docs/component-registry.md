# 元件双注册与性能验证

## 新增普通组合元件

仅需增加两个自包含文件，重新运行 CMake 配置后构建：

1. `src/components/builtin/Foo.cpp`：定义 `Components::Definition` 的派生类，实现稳定 `typeId()`、端口数量/位宽/局部几何及 `compute()`，可覆盖 `defaults()`；导出 `std::unique_ptr<Definition> createFooDefinition()`。可参考 `Not.cpp`、`And.cpp`。工厂名必须与文件名一致。
2. `qml/components/builtin/FooDefinition.qml`：继承 `ComponentDefinition`，使用同一 `typeId`，声明库名称/分类/顺序、尺寸、绘制回调和可选内嵌 `propertyEditor`。可参考 `NotDefinition.qml` 和 `LedDefinition.qml`。

CMake 在限定目录自动发现文件，生成显式 C++ 工厂引用和 QML 清单，避免静态库链接裁剪及不确定的全局初始化顺序。不需要编辑中央元件库列表、Painter 类型分支或仿真引擎。注册定义按类型复用，而非每个电路元件建立一份 QML 定义对象。

C++ 负责仿真语义、默认属性和端口几何；QML 负责外观、库信息及编辑器，不应另算端口位置。启动时 `Circuit::registeredComponentTypes()` 用于校验两侧类型。持久化 type ID 一旦发布不可改名。未知类型保留旧有回退行为。

`ComponentLogic` 是兼容门面；两引擎共享注册求值。定义的组合计算应为纯函数，不访问队列、不推进时间、不修改模型。时钟、输入源和层级子电路等特殊能力由 Role 描述，但任意新增的时序状态机并不自动获得新的调度语义：本次没有更改调度契约。

## 已保留的历史行为

本次迁移保留了原分线器/集线器的位序、传输门存储输入数与逻辑输入数的差异，以及 clock/const 的创建初始值等历史行为，不借重构改变功能。现有 `logic_test_component_logic` 分线器期望与实现冲突，备份基线同样失败，未修改其期望掩盖问题。

## 性能改动

- 多驱位解析直接右对齐索引源字符串，避免每一位重复补齐/截断分配。
- 事件引擎已知节点通过整数索引记录脏标记，保留首次标记顺序与公开 qid 接口。
- 拓扑坐标使用无碰撞的两个 32 位坐标打包键；正交线段按行列建立候选表，再依原线段顺序归并，保持并查集与虚拟线行为。
- 模型缓存连接圆点，变更通知保守失效，纯视图重绘不再重复构建拓扑。
- 绘制尺寸和图形移至注册定义，仍使用原有 Canvas 命令，不降低画质、不删图层。

性能 harness 的独立构建与比较方法见 `tests/perf/README.md`。基准采用相同 Qt 6.11.1、Release、固定工作量及固定哈希种子。不要比较不同构建模式，也不要将特定密集多驱场景的收益当作所有电路的收益。

## 验证记录与限制

- 19 个类型的 310,000 项逻辑/几何对照通过；另有 7,416 个模型默认值、几何及计算特征用例与备份 JSON 逐字节一致。
- 5,760 组真实 QML 定义调用的 Canvas 命令/样式与尺寸对照一致，涵盖旋转、选择、缩放、简化模式、四态、标签、输入块和端口名。
- 独立两文件扩展探针 9 项全部通过：自动发现、C++ 注册、两引擎计算、QML 元数据/库条目、内嵌编辑器与 paint 回调；测试环境提供了现有 LogicSim Theme 模块。
- 尚无真实 Canvas 像素截图对照、完整 GUI 交互验收及受控整帧性能报告。命令等价测试不替代像素和交互验收。
- 未实现全量 GPU 重写、后台仿真、多线程模型或事件去重；保留事件顺序、事件数、run budget、延迟、暂停、振荡和单步语义。
