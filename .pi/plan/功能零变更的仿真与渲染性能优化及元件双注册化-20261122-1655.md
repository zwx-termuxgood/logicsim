## 目标与不可突破的约束

在**不改变现有功能、仿真语义、交互行为、存档格式兼容性和视觉效果**的前提下，尽最大努力提升仿真与渲染性能，并将元件扩展改为注册式：通常新增元件只需实现一个 C++ 元件定义类和一个 QML 元件定义类，不再修改引擎、画布、元件库、属性面板中的类型分支。

本轮仅审阅方案。**批准后先 Git 备份并核验，成功后才修改代码。** 不承诺未经测量的倍数提升，也不以删功能、降画质、改变事件顺序或跳过仿真工作换取跑分。

## 3. 元件 C++ 注册体系

**新增：** `src/components/ComponentDefinition.{h,cpp}`、`ComponentRegistry.{h,cpp}`、`builtin/` 下的内置元件定义及构建文件。

**接入：** `src/logic/ComponentLogic.{h,cpp}`、`src/model/impl/Circuit_component.cpp`、`Circuit_lifecycle.cpp` 中的元件专属查询、`src/engine/event/*`、`src/engine/iter/IterEngine.cpp`、相关 CMake。

### 契约

- 每种元件定义稳定的存档 type ID、默认属性、属性约束、输入/输出端口及位宽、整数局部端口几何、元件角色和求值行为。
- 通用描述支持数据源、时钟、组合逻辑、探针/显示、纯文本、层级子电路等能力；引擎按能力执行，而不是不断扩充 type 字符串判断。
- 层级展开、调度、时钟推进与子电路实例状态仍由模型/引擎负责；定义类不自行操作队列、不改全局状态。
- 允许按实例配置编译轻量求值描述，将位宽、分段和求值回调在构建时解析，运行时不反复查注册表或转换 QVariant。
- `ComponentLogic` 保留现有调用接口作为兼容门面，内部逐步转发到注册定义，避免一次破坏所有调用方。
- 注册表启动时建立，显式处理重复 ID、缺失定义及未知存档类型；未知类型保持既有兼容行为，不静默删除或映射为其他元件。
- 逐类迁移现有元件，保留 type ID、属性名、默认值、位序、E/Z 行为和序列化结果；迁移不是修正既有逻辑语义的机会。

### 扩展成本

- 新增一个自包含的 C++ 定义实现文件和一个同名 QML 定义文件；一次性在限定的元件目录实现构建期发现/清单生成，支持重新配置后自动纳入，不做运行时扫描源代码。
- 自动生成的引用必须保证静态库链接时注册代码不会被裁掉；不得依赖不可控的静态初始化次序。
- 新增普通元件不再编辑主程序、引擎、中央 Painter 分支、元件库列表或属性面板。
- 此次不新增用户可见元件；用测试专用示例验证两文件扩展流程。

## 4. 元件 QML 注册体系

**新增：** `qml/components/ComponentDefinition.qml`、注册服务与 `builtin/` 元件定义。

**接入：** `qml/views/panels/LeftPanel.qml`、`PropertyPanel.qml`、现有 `props/`、`qml/views/canvas/{Painter.js,CanvasView.qml,Geometry.js}`、`qml/Main.qml`、顶层 `CMakeLists.txt`。

- 每个 QML 定义提供 type ID、现有库分类/顺序/名称、绘制回调、尺寸/命中描述、交互能力，以及可选的专属属性编辑组件。
- C++ 是端口与仿真语义的唯一来源；QML 不重新计算另一套端口位置/位宽。两侧 type ID 启动时校验。
- 保留当前 Canvas 的绘制方式和现有图形命令，将各类型分支平移到定义类，公共选择框、端口、旋转和标签框架复用。
- 公共属性编辑器按描述生成，专有属性通过定义中的内嵌 `Component`/编辑器接入。原有快捷操作、输入校验、焦点、数值递增和错误提示不改变。
- 注册定义对象按类型复用，不为每个画布元件实例建立一个重型 QML 对象；不把大画布改成数万个 Loader。
- 现有 `.js` 工具只保留公共绘制与几何函数，不保留需要新增元件时继续修改的中央类型分派。
- 所有内置类型逐一验证库顺序、外观、尺寸、旋转、命中、属性面板及输入操作。

## 5. 仿真优化：先消除重复工作，再优化热点数据结构

**涉及：** `src/engine/event/*`、`src/engine/iter/IterEngine.cpp`、`src/logic/{ComponentLogic,WireNetworkSolver}.*`、`src/model/Circuit.h`、`src/model/impl/Circuit_lifecycle.cpp`、必要的 `src/core/` 辅助类型。

### 可优先实施的等价优化

- 多驱解析在位循环之外完成规格解析，或通过只读索引访问虚拟补零/截断，避免位数×驱动数的临时字符串分配；严格保持 0/1/E/Z 的现有解析顺序和规则。
- 构建时预解析类型定义、位宽、分段、门延迟和端口索引；运行时使用稳定的节点/端口/驱动整数索引及紧凑邻接表，减少字符串键与 QVariant 查找。
- 内部脏节点使用索引标记和可复用缓冲区，边界处才转换 qid；保持外部可见顺序和输出查询接口。
- 合理 reserve、复用向量与临时输出缓冲区，避免重复计算未变的元件配置与端口定义。
- 在拓扑内部将字符串坐标键改为无碰撞整数点键，采用按行/列的线段候选索引，减少“每个位置扫描所有线段”；保持端点、T、重叠、纯 X 的精确整数语义。
- 同一上下文、同一几何版本复用拓扑分析产物，用于虚拟线和连接圆点；明确缓存所有者、生命周期及失效入口。
- 迭代引擎优先优化每轮分配、配置解析、层级索引和虚拟线复用，不直接更换为可能改变环路收敛过程的算法。

### 严格受控事项

- 事件的 `(time, seq)` 稳定顺序、单步粒度、延迟、run budget、仿真时间、暂停时不传播、振荡和多驱结果全部不变。
- 不直接合并/丢弃“看似重复”的事件，因为可能改变单步、预算和瞬态；只有证明全部可观察行为等价且有测试覆盖，才采用相关优化。
- 不通过改变仿真工作量、定时器速度、振荡上限或停止条件提高吞吐。
- 不将几何移动一概视为“无需求值”：移动可改变接触拓扑，运行态编辑还可能重置引擎状态，需按现有语义处理。
- 缓存仅跳过语义上可复用的中间计算，不绕过现有必须发生的重建/初始化行为。
- 默认不引入后台仿真线程，避免线程时序、对象生命周期和输入事件顺序变化；只有测量证明必要且能保持契约时，另行说明，不隐式扩大范围。

## 6. 渲染优化：减少全量桥接和无效绘制

**涉及：** `qml/Main.qml`、`qml/views/canvas/{CanvasView.qml,Painter.js,Geometry.js}`、交互脚本、模型信号及必要的渲染数据/空间索引辅助类。

1. 区分拓扑/几何/配置/值/选择/视图版本；同一次操作只刷新相应缓存，不因颜色变化重新计算端口和连通。
2. 模型保留已有 API，提供增量值变更或批量快照接口，减少高频全量 QVariantList→JS 转换；无关属性面板和元件库不随每个仿真 tick 重建。
3. `connectionDots()` 按几何版本缓存，不在每帧重建电气拓扑；缩放、平移和选中变化不使拓扑缓存失效。
4. 建立元件/线路包围盒与空间索引，绘制及命中只查询可见候选；候选仍按原绘制和命中优先级排序，保留重叠选择行为。
5. 包围盒覆盖旋转、端口、文字、选择边框、粗线及抗锯齿边缘，避免边界漏画；贝塞尔线使用可靠曲线边界而非仅看端点。
6. 合并同一显示帧的冗余重绘请求，但不减少仿真步数或延迟输入反馈；仿真状态计算与显示刷新解耦，屏幕显示最新完整状态。
7. 在基准和截图对照下评估背景网格缓存、公共形状缓存、静态/动态覆盖层与局部脏区域；只有原有图层遮挡、颜色、文字、线宽、DPI 和抗锯齿效果不变时采用。局部重绘必须清除旧位置与旧选框。
8. 核查 Canvas 的 `renderStrategy/renderTarget` 设置及 Qt 6.5+ 兼容性，不把设置名称或注释当作实际 GPU 加速证据。

**本轮不以全量改写 QSG/自定义 GPU 渲染器为默认路线。** 先优化现有 Canvas 与数据通路；如果测量表明 Canvas 本身仍是瓶颈但替换无法证明视觉等价，则报告限制，不强行改变画法。

- 保持现有 type ID、元件/线路 ID、属性键、存档字段与旧数据迁移规则；不清空未知字段。
- 保留已修复的正交线移动、缩短、圆点、复制粘贴、删除与一次手势撤销行为。

## 8. 实施顺序、复核与验收

1. Git 备份并核验。
2. 建立基线、特征测试与可重复性能场景。
3. C++/QML 注册基础，逐类迁移并与基线对照；保留兼容门面直到调用方全部迁移。
4. 实施多驱/分配/索引等低风险热点优化。
5. 共享拓扑缓存与空间候选索引。
6. 模型到 QML 的增量同步、视口裁剪和帧请求优化；缓存/图层优化按实测采用。
7. 独立只读代码审查，修复所有功能等价、缓存失效和事件顺序问题。
8. 全量构建、CTest、QML 静态检查、基线差分、旧文件往返与实际 GUI 验收。

### 功能验收

- 所有内置元件的定义、创建、仿真、绘制和属性行为与基线一致。
- 单步、连续运行、暂停、时钟、复位、延迟、预算边界、多驱 E/Z、环路振荡及嵌套子电路通过差分测试。
- 渲染截图在相同平台、字体、DPI 和软件/图形后端下对照；抗锯齿允许的差异必须限定且解释，不能容忍漏图、错色或遮挡变化。
- 实际画布验收：缩放/平移、框选/重叠命中、拉线/裁剪、整体/混合移动、删除、撤销/重做、输入编辑、子电路浏览及保存重开。
- 测试专用新增元件只添加两份定义文件即可被构建发现、显示于测试库、参与两引擎计算并加载专属属性，且无需改中央类型分支。

### 性能验收与交付

- 同机、同编译选项、相同输入工作量，多轮测量并记录时间分布与内存；不得只比较 Debug 和 Release。
- 分别报告小电路、大电路、运行态、编辑态的收益与回退，不只展示最优样例；无稳定收益或导致明显回退的复杂优化撤回。
- 最终提供修改范围、注册接口与两文件扩展示例文档、前后性能表、备份引用、测试统计及未验证项。
- 未运行的 GUI 验收不宣称通过；既有失败单独报告，不改测试期望掩盖问题。

## 范围与风险控制

这是高风险的跨层重构，按可验证阶段推进，优先正确性而不是改动规模。尽最大努力优化不等于承诺理论最优：若优化与“功能绝对不变”冲突，保留功能并说明剩余瓶颈。禁止未经验证地更换位序/电平编码、重排事件、简化振荡、多线程化模型或降低渲染细节。所有临时基准输出与构建产物放在会话 scratch，不污染工作区。
