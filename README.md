# LogicSim

一个基于 **Qt 6 / QML / C++17** 的数字逻辑电路模拟器，支持多比特位宽、子电路嵌套、事件驱动仿真、传输门与晶体管元件，可构建桌面端和 Android 应用。

本项目主要由 AI 辅助生成，作者进行了调试与优化。仅供学习、实验与个人使用，不适用于对可靠性有严格要求的场景；专业电路仿真建议使用 [Logisim-evolution](https://github.com/logisim-evolution/logisim-evolution)。

## 为什么做这个

Logisim 很好用，但移动端和小屏幕上的操作需求不同。本项目采用按下—拖动—释放的拉线手势，支持贝塞尔线和正交线；正交线还支持从已有线段中间 T 型引出、切换拐角方向、沿原路径缩短。

功能尽量向 Logisim 看齐，交互则尽量适应触屏和小屏幕。项目仍可能存在边界问题，欢迎用可复现电路与操作步骤反馈。

## 核心功能

### 电路建模

- 1～64 位多比特位宽。
- 二进制、无符号十进制、有符号十进制、十六进制、单精度和双精度浮点显示。
- AND / OR / NOT / NAND / NOR / XOR / XNOR。
- 传输门、NMOS、PMOS，支持高阻态 `Z` 与错误态 `E`，多驱冲突按现有规则解析。
- 分线器、集线器，可配置分段进行总线拆分与拼接。
- 自定义子电路、嵌套实例、循环引用检测、设为主电路、只读实例浏览和端口同步。
- 时钟频率调节、启停、手动翻转、复位等操作。

### 编辑与交互

- 编辑 / 控制 / 选择三种模式。
- 放置、移动、旋转、改属性；框选、多选、复制、粘贴与批量删除。
- 滚轮缩放、空白处拖动平移、视野外元件导航。
- 贝塞尔 / 正交 / 可切换线型。
- 正交线采用整数世界坐标，自由绘制和移动使用 10px 吸附；已有端口所在的精确整数行列不再强制改为 10px 倍数。
- 正交折线整体选择移动、元件随动、拐点编辑、T 型接入和沿原路径缩短。
- 连接圆点与电气网络共用拓扑规则：明确端点和端口接入会连接，纯内部十字穿越不会自动连接。
- 撤销 / 重做；选择移动手势从起始快照计算累计位移，一次手势可一次撤销。
- 框选集合中的正交线与元件可一起删除。

### 工程与文件

- JSON 存档格式 version 11，保留旧文件兼容与几何迁移入口。
- 加载时可容错提取首个完整 JSON 对象并回写修复。
- 导入外部电路时添加 ID 前缀；支持重复导入替换、卸载导入。
- 最近文件列表、递归电路统计、位宽不匹配等错误检查。
- 桌面端和 Android 构建支持。

## 两套仿真引擎

| 引擎 | 行为 | 适用场景 |
|---|---|---|
| 事件驱动（默认） | 有仿真时间；按时间与序号处理事件；支持门延迟、线延迟、按类型延迟配置及单步 | 时序、振荡、延迟敏感电路 |
| 迭代 | 无独立时间推进；组合部分求值并对反馈环路执行有限次迭代 | 组合逻辑与快速静态求值 |

事件引擎必须手动“开始仿真”。未开始时可以编辑输入元件自身的值，但不向下游传播；暂停、复位与启动的职责不能与迭代引擎混淆。

两套引擎通过相同的元件定义计算组合逻辑，但调度与收敛方式不同，不能将两者的时间轨迹视为相同。振荡电路在事件引擎中会持续消耗事件预算，而不是保证一次调用收敛。

## 元件库：C++ / QML 双注册

元件类型知识不再集中堆叠于引擎、Painter 和面板的类型判断中：

- **C++ 定义**：稳定 `typeId`、角色、默认值、端口数量/位宽/局部几何及逻辑计算。
- **QML 定义**：同一 `typeId` 的名称、库分类与顺序、尺寸、绘制回调及专属属性编辑器。
- **模型实例**：保存 ID、位置、属性、输入输出值等实例状态；类型定义按类型共享。
- **引擎**：管理时序、事件队列、传播与层级展开；组合定义不自行操纵调度。
- **公共界面**：元件库、Canvas 和属性面板查询注册定义，不为每个画布元件建立重型定义对象。

通常新增一个普通组合元件，只需增加：

```text
src/components/builtin/Foo.cpp
qml/components/builtin/FooDefinition.qml
```

C++ 文件导出与文件名对应的 `Components::createFooDefinition()` 工厂，QML 文件继承 `ComponentDefinition`；两边使用相同的类型 ID。重新配置 CMake 后，构建系统自动发现定义并生成显式工厂引用与 QML 清单，无需编辑中央元件列表。

这是一套**编译期扩展机制**，不是运行时第三方插件系统。新时序状态或全新调度能力仍需要框架支持，不能仅靠组合 `compute()` 函数获得。端口电气几何以 C++ 为唯一来源，QML 不维护另一套端口规则。

接口与验证说明见 [docs/component-registry.md](docs/component-registry.md)。

## 界面与基本操作

- **菜单**：保存、另存为、打开、导入、已导入、最近、统计、新建和设置。
- **顶部栏**：编辑模式、线型切换、撤销/重做、缩放、上下文选择和未保存标记。
- **时钟栏**：事件仿真开始/暂停/单步/复位，时钟启停、时钟拍、输入复位及频率。
- **左侧元件面板**：输入输出、基本逻辑门、复合逻辑门、传输门/晶体管、工具、控制，以及自定义子电路。
- **属性面板**：名称、方向、位宽、输入数、进制、门延迟和类型专属属性，以及多选、线路、子电路操作和错误列表。

操作示例：

1. 左侧选择元件，再点击画布放置。
2. 编辑模式拖动元件；选择模式在空白处拖出选框，再移动选中集合。
3. 按下端口、拖动、释放到目标端口完成连线。
4. 正交线可从线段中间引出；缩短操作沿原折线路径裁剪。
5. 双击子电路实例进入查看；使用上下文导航返回。
6. 滚轮缩放，空白拖动平移；视野内无元件时可用导航指示器定位。

| 快捷键 | 功能 |
|---|---|
| Ctrl + Z | 撤销 |
| Ctrl + Shift + Z / Ctrl + Y | 重做 |
| Delete | 删除当前选中集合或单个选中对象 |
| Ctrl + C / Ctrl + V | 复制 / 粘贴 |
| Back（Android） | 进入退出流程 |

## 构建与测试

依赖：**Qt 6.5+、CMake 3.16+、C++17 编译器**。当前 CMake 需要 Qt Core、Qml、Quick、QuickControls2 和 Test 模块。

### 桌面端

```bash
git clone https://github.com/zwx-termuxgood/logicsim.git
cd logicsim
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
./build/LogicSim
```

Qt 不在默认搜索路径时，在配置阶段添加 `-DCMAKE_PREFIX_PATH=<Qt安装目录>/<版本>/<工具链>`。多配置生成器需在构建和测试时指定对应配置。

```bash
ctest --test-dir build --output-on-failure
cmake --build build --target LogicSim_qmllint
```

无显示服务器时，可在支持的平台使用 `QT_QPA_PLATFORM=offscreen` 运行模型测试。离屏启动、静态检查和绘图命令测试不等于完整 GUI 交互验收。

现有测试目录覆盖 core、logic、io、engine、move 和 model；包含注册兼容性与事件等价回归，但部分测试目标仍只有占位断言，不代表相应模块已获得完整功能覆盖。已知分线器测试期望与原实现存在位序冲突，具体结果应以当前本地运行日志为准。

### 性能基准

`tests/perf/` 是独立 CMake 工程，可用相同基准源码测量不同源码树。它不作为普通 CTest 的绝对耗时门槛，输出包括中位数、p95 和语义指纹。

完整复现命令见 [tests/perf/README.md](tests/perf/README.md)。应使用相同 Qt、编译选项、工作量与哈希种子，多轮测量；共享主机微基准不能直接解释为实际帧率或所有电路的加速比。

### Android 与 Windows

- **Android**：用 Qt Creator 打开 `CMakeLists.txt`，选择已配置的 Android Kit 构建部署。
- **Windows 交叉编译**：`qtWin.sh` 是作者使用的 MXE 脚本，路径和工具链依赖本地环境，不能保证直接运行。

## 项目结构

```text
logicsim/
├── CMakeLists.txt          # 六个静态库、应用、QML 资源与测试入口
├── src/
│   ├── core/               # 上下文、ID、值编解码、撤销数据与整数网格
│   ├── components/         # C++ 定义与 19 个内置类型；编入 logicsim_logic
│   ├── logic/              # ComponentLogic 兼容门面、整数连线拓扑
│   ├── io/                 # JSON、剪贴板、最近文件
│   ├── move/               # 避让、连接器、A* 和移动辅助接口
│   ├── engine/             # event/ 事件引擎、iter/ 迭代引擎
│   ├── model/              # Circuit 主类和 impl/ 分部实现
│   └── app/                # main.cpp，QML 类型注册与启动
├── qml/
│   ├── Main.qml            # 模型实例、同步缓存、选择状态、快捷键和布局
│   ├── Theme.qml           # 主题单例
│   ├── components/         # QML 定义契约、注册服务和 builtin/ 定义
│   └── views/              # bars、canvas、panels、dialogs
├── tests/                  # 功能回归；perf/ 为独立性能工程
├── docs/                   # 元件扩展与验证说明
├── android/                # AndroidManifest 和图标
├── qtWin.sh                # MXE 构建辅助脚本
├── map.md                  # 详细文件职责与阅读导航
└── README.md
```

依赖方向：`core → logic → {io, move, engine} → model → LogicSim`。`components/` 是源码组织目录，不是额外的第七个静态库。

模型以 `QVariantMap` / `QVariantList` 保存可复制实例状态；QML 经 `Q_INVOKABLE` 和信号访问模型。`renderSnapshot()` 同步复用相同列表存储，减少重复信号的列表桥接；圆点缓存保守失效。Canvas 仍使用既有绘制命令，并未整体改写为自定义 GPU 渲染器。

详细文件说明见 [map.md](map.md)。

## 已知限制

- 事件引擎的单次运行有事件预算，大电路可能需要多次推进；反馈振荡不会保证收敛。
- 深层子电路和密集拓扑仍可能消耗较多资源，现有递归保护不能替代规模评估。
- `move/` 中的 A*、线程连接器是移动辅助子系统，不应据此认为所有当前拖动都走后台 A*；正交线手势还使用模型的快照移动路径。
- 存档兼容、回归与语义指纹测试不能证明任意电路绝对正确；真实 GUI、像素一致性和性能验收需要单独执行。
- 不承诺 Windows 脚本在作者环境之外直接可用。
